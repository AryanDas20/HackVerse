# HackVerse v5.7.1 implementation and deployment notes

## Included in this archive

- Responsive layout overrides for phone/tablet widths, including hero, saved opportunities, navigation, chat, AI panel, forms and dialogs.
- Firebase auth state now re-evaluates member-only routes as sign-in state changes.
- Sign-up/sign-in buttons show a busy state while Firebase is processing; email/password sign-up sends a verification email and requires verification before member access. Google sign-in remains available.
- AI Chatbot and AI Wish retain separate modes, histories and visible transcripts. Chatbot prompts are for general questions and website help; AI Wish prompts are for supported website actions, follow-up questions, review and explicit approval.
- Existing direct/group chat features retained: live updates, typing indicators, read/delivery timestamps, search, unread filters, archive/pin preferences, reply, reactions, copy, forward, star, edit/delete, attachments and voice notes.
- Existing manual group creation, group name/description/photo URL, group roster, profile viewing and admin membership controls retained.
- Profile photo upload endpoint and styled in-app confirmation/input dialogs.
- Draft Privacy Notice and Terms pages. Owner must review and complete them before public launch.

## Required setup

1. Vercel project root directory: `./`; output directory: `public`; Node.js: `22.x`.
2. Keep existing Vercel credentials in Environment Variables. Never place Firebase service-account JSON or a Supabase secret key in frontend files or GitHub. Rotate any credentials that were previously pasted into chat or shown in screenshots.
3. For chat media, keep Supabase Storage bucket `chat-media` **private**. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_STORAGE_BUCKET=chat-media` must all belong to the same Supabase project. The browser file `public/supabase-config.js` uses only the public `sb_publishable_` key.
4. For profile photos, create a separate Supabase bucket named `profile-avatars`, set it **public** (the UI currently saves public avatar URLs), and set `SUPABASE_PROFILE_BUCKET=profile-avatars` in Vercel if not using the default. Do not make `chat-media` public. The upload endpoint is authenticated, but profile images in this bucket are public.
5. Publish the updated `firestore.rules` in Firebase Console → Firestore Database → Rules. Vercel deployment does not publish Firestore rules automatically.
6. Commit and push the extracted project contents to GitHub `main`, then confirm the Vercel deployment is Ready.

## Important feature boundaries

- AI Wish can apply only the action types implemented and validated by this application. It is not an unrestricted computer-use agent and cannot safely perform arbitrary external actions.
- Chat pin/archive/star preferences are currently browser-local; they do not sync across devices.
- Voice notes are supported, but real-time voice/video/group calls and screen sharing require WebRTC signaling, TURN infrastructure, and additional UI/server work.
- Message and media transfer use HTTPS, Firebase authorization and signed media URLs; this release is **not end-to-end encrypted**.
- Desktop/browser notifications are best-effort while the website is open. Reliable background push delivery needs a service worker and push infrastructure.
- Disappearing messages, custom per-chat sound/quiet hours, join approvals/invite links, username changes, contact calls, complete moderation workflow, automated account erasure and legal compliance workflows need dedicated backend work and security review before they should be advertised as available.
- The privacy and terms pages are drafts with contact placeholders. Have them reviewed and complete them before commercial publication.
