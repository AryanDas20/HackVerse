## Brand system

- Product name: **HackStop**. User-facing page title, nav/footer wordmark, favicon, web manifest, Open Graph/Twitter metadata, auth screen and app copy use the new name.
- Palette: sky-blue links/information, soft-pink primary actions, very light blue-gray light surfaces and deep navy dark surfaces.
- Typography: Inter, 16px base body text, 1.5+ paragraph line-height, controls at least 44px high, 16px form control text to avoid iOS zoom.
- Mobile layout: collapsible navigation, stacked cards and forms, bottom-sheet modals, single-column directory, fixed/sticky chat composer with safe-area padding, overflow clipping and reduced-motion support.
- Brand email caveat: Firebase verification and password reset messages are generated by Firebase Auth. Configure sender, templates, authorized domains and any custom SMTP in Firebase Console; HTML changes cannot alter those emails. Replace `hello@hackstop.example` with a monitored address.

## Chat UX flow

1. Select a direct or group conversation.
2. Click the direct conversation title or a message author's name to open the person's dedicated profile page.
3. Message controls: Copy, Reply, emoji reaction, Report and Block for other participants; Edit and Delete for the current user's messages within 15 minutes. Edited messages show an Edited label; deletes are soft-deleted markers.
4. Blocked direct conversations are hidden locally and Firestore rules prevent sending a new DM when either side has blocked the other. Existing group chat remains group-scoped.
5. Group details display the current member list. Admin additions are invitations, not immediate membership changes. Non-admin members can leave a group; the creator manages removal and deletion.

**Not included:** attachments, calls, forwarding, presence, typing indicators and read receipts.

## Group/team deletion flow

1. Only the creator sees the permanent-delete control.
2. The warning modal explains that the group/team conversation, messages and membership are removed.
3. Exact phrase is required: `DELETE GROUP` or `DELETE TEAM`; button remains disabled until exact match.
4. The client writes member notifications and an `auditLogs` record, deletes message documents in batches, then deletes the conversation document. Rules restrict conversation deletion to its creator.

## Community members page

- Main community page shows a View Members call-to-action rather than exposing a full username list immediately.
- Directory search normalizes case, whitespace and accents; partial/fuzzy search covers public name, handle, college, short college name, course, skills, interests, bio and public contact fields.
- Filters include role, skill, college, study level, availability, interest and looking-for-team.
- Cards provide View Profile, Chat and Contact. Contact opens an in-app contact sheet showing only explicitly shared public email/phone. Private profiles have no `publicProfiles/{uid}` record.

## Team Generator flow

- Essential fields: project/team name, target size (2–10), needed skills and availability.
- Optional fields: skill level, college, college year, course, location, hackathon name/link, communication preference, visibility, join policy, description and project idea.
- Candidate ranking uses exact skills first and a related-skill map (e.g. React ↔ JavaScript/Next.js/TypeScript/Tailwind). It includes optional availability, level and same-college reasons. It is deterministic matching, not generative AI.
- A selected person receives a seven-day invitation with team name, creator, required skills, target size and optional hackathon metadata. Membership is appended only when the invitee accepts. Declined/expired invitations do not add a member.
- No team larger than 10 is accepted by the client or Firestore rules.

## Notification center

- Categories: All, Teams, Chat, Hackathons, Community, System.
- Unread count, mark-all-read, clear-all and direct action links are included.
- Current generators: new chat message, team/group invite, invite response, and group/team deletion. Invitations have Accept/Decline actions and an expiry date.
- Chat notifications open the relevant conversation; invitation responses and deletion messages link to the workspace; event notifications can link by `eventId`/`targetHash` when such notification documents are created.

**Not yet enabled:** automated event matching/deadline notification generators, profile-view alerts, project likes/comments/follows, email delivery and Web Push. Category muting is available in the in-app notification preferences. These require trusted scheduled/event handlers, preferences, and external delivery configuration.

## Firestore schema additions

| Path | Key fields | Purpose / authorization |
|---|---|---|
| `users/{uid}` | `profileData`, `profileVisibility`, `phoneVisibility`, `emailVisibility`, `blockedUsers`, `mutedNotificationCategories` | Private account/contact details; owner only |
| `publicProfiles/{uid}` | curated public fields, `skillLevel`, `tracks`, `publicEmail`, `publicPhone` | Public search only when profile is Public; contact fields opt-in |
| `conversations/{id}` | `isGroup`, `entityType`, `createdBy`, `admins`, `participants`, `teamSize`, `requiredSkills`, `availability`, optional team metadata | Direct conversations and group/team rooms; max 10 members |
| `conversations/{id}/messages/{id}` | `authorUid`, `text`, `createdAt`, `edited`, `deleted`, `replyTo`, `reactionsByUser` | Member-read; author-only edit/delete for 15 minutes; reactions map UID → emoji list and rules only allow the acting UID key to change |
| `teamInvitations/{id}` | `conversationId`, `fromUid`, `toUid`, `requiredSkills`, `teamSize`, `status`, `createdAt`, `expiresAt`, `respondedAt` | Sender/recipient read; recipient accepts/declines pending invite |
| `users/{uid}/notifications/{id}` | `type`, `category`, `title`, `body`, actor, conversation/invite/event link, `expiresAt`, `createdAt`, `read` | Recipient read/update/delete; constrained create types |
| `auditLogs/{id}` | `action`, `actorUid`, `conversationId`, `affectedUsers`, `createdAt` | Creator write for group/team deletion; admin read |
| `reports/{id}` | `createdBy`, `targetUid`, `category`, `details`, `status`, `createdAt` | User submits; admin reviews |

## API / operation list

This app is primarily a Firebase Web SDK client. The following are client-side operations, not public REST endpoints:

- Auth: Firebase Auth Google popup, email/password create/sign-in, reset and verification.
- Profiles: transactional writes to `users`, `publicProfiles` and `usernames`.
- Community search: `publicProfiles` query by normalized prefix and skill/interest array fields.
- Messaging: create/read conversation docs and nested message docs; transactions for per-user reactions and invitation acceptance.
- Teams: create a group/team conversation, create `teamInvitations`, accept/decline invite, remove member, creator-only delete.
- Notifications: listen to `users/{uid}/notifications`, mark read, clear, open deep link.
- Reports: create `reports` documents.
- Discovery callable functions retained: `runDiscoveryNow`, `addDiscoverySource`, `setDiscoverySourceEnabled`, `socialConnectorStatus`; scheduled `scheduledRssIngestion` exists in functions code but should not be deployed on Firebase Spark. GitHub Actions is the six-hour scheduler.
